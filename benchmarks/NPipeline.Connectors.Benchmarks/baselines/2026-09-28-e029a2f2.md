# Connector benchmark baseline: 2026-09-28, e029a2f2

The baseline before any connector fixes (the state reviewed in the connector review). Measured on an Apple M1 Max
(10 cores), macOS 26.6.2, .NET SDK 10.0.401, with BenchmarkDotNet 0.15.8 (`IterationCount=8, WarmupCount=2,
LaunchCount=1`). Row counts are in the [README](../README.md); every row has 20 columns.

Two numbers to watch as phase 3 and 4 land:

- **Parquet read** is slower than CSV read (745 ms against 426 ms on net10.0) and allocates 1.4 GB per 100,000 rows.
  Reading 3 of 20 columns still allocates 1.2 GB, because every row is materialised as boxed values for all columns
  (PQ-P1, PQ-P3, PQ-6).
- **JSON read** allocates about 1.75 GB per 100,000 rows, roughly 7 times the file size (JSON-P1, JSON-P3).
